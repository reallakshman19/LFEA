## 1. What LFEA is

LFEA is a standalone browser app for linear finite-element piping analysis,
extracted from `reallakshman19/AA3` at `a8650bb`. It takes a CAESAR II
InputXML or ACCDB model through these steps:

- **Source:** import, health check, pre-flight.
- **Run:** a linear frame solve per load case.
- **Results:** displacements, forces and support loads.
- **Code:** ASME B31.3 sustained check.
- **Verification / Dossier:** provenance, history and compare.

The work is benchmarked against real CAESAR output for BM1 and BM4, which
live in `benchmarks/LFEA/`.

The governed chain is unchanged: **stage → authorize → publish** for each
authority. Each authority (support, B31, …) keeps a sealed record with a
semantic hash and reports itself STALE when its parents change.

### 3.1 `06df293`: B31.3 sustained check includes pressure

**Pressure effects no longer block the check.**
- Changed in
  `src/core/linear-piping-code-application/pressure-stress-derivation.js`.
- Axial thrust, Bourdon and pressure stiffening are all applied by the solver
  (frame-element.js, the Bourdon augmentation, bend-component.js). They are
  now `SOLVER_APPLIED_PRESSURE_EFFECTS` and disclosed as
  `:SOLVER_APPLIED_…` in the pressure term's source.
- The refusal path (`PIPING_B31_PRESSURE_EFFECT_NOT_IMPLEMENTED`) is kept
  with an empty table. A future effect that the solver does not apply is
  still blocked.

**Pressure term formula.**
- The term is now `P·di²/(Do²−di²)`, the B31.3 form and what CAESAR reports
  as SLP. The old `P·Do/4t` is the B31.1 form.
- The formula ID is `B31_3_LONGITUDINAL_PRESSURE_STRESS_AREA_RATIO_V1`.

**Sustained section.**
- `src/lfea/native-b31-authoring.js` builds the sustained section with
  `resolvePipeSection` as the nominal wall minus `CORR_ALLOW`. The allowance
  is read from
  `preFlight.diagnostics.sourceBundle.elementRecords[].fieldEvidence.CORR_ALLOW.canonicalValue`
  in metres, explicit or inherited.
- Mill tolerance is not deducted. This matches CAESAR.

**Core wiring.**
- `src/core/linear-piping-code-application/b31-application.js` now derives
  pressure from `sustainedSectionResolution` for SUSTAINED checks, so
  supplied and derived values agree.

**Removed.**
- The weight-only fallback in `src/lfea/practical-b31-check.js` is gone,
  because it can no longer trigger.

**Results label.**
- The "Code check basis" row now states the corroded wall and the pressure
  formula.

**New check:** `scripts/lfea-b31-sustained-caesar-comparison.mjs`, registered
in `scripts/ci-checks.json`.

Gotchas:

- **`src/lfea/standalone-runtime.js` must stay under 300 lines.** It is at
  299, and several checks assert the limit. Put new logic in modules such as
  `practical-run.js` and leave the limit alone.
- **Source guards.** Many `*-source-guard.mjs` scripts regex-check code
  shape. If you change a formula or contract on purpose, update its guard and
  test in the same commit. `scripts/lfea-b4.2-*` is the example from
  `06df293`.
- **InputXML gravity is −Y** (`INPUTXML_DEFAULT_GRAVITY_DIRECTION`).
- **InputXML units.** `CORR_ALLOW` `canonicalValue` is in metres, while
  `WALL_THICK` `canonicalValue` is in mm. Sections are in metres.
- **The B31 engine requires:**
  - profile ID `LINEAR-B31-CODE-PROFILE-R1`;
  - `editionStandard` `ASME_B31_3_2024`;
  - one edition dataset per `materialId`;
  - SUSTAINED checks use Sh at the material's `evaluationTemperature`.
- **BM4** runs only its weight case unless `['IXP-W','IXP-WP']` is requested.
- **CAESAR output layout.** Each `<STRESS_REPORT LOADCASE="CASE n (SUS) …">`
  block holds per-element `CODE_STRESS`. A detail block in the same case
  holds `SLP`, `F_A` and `BENDING_STRESS`. Values are in kPa.

## 5. What's next (ranked)

### A. One-way (unilateral) supports (recommended next)

**Why first:**
- It is the largest remaining error. It drives most of BM4's sustained
  misses (13 of 116 outside 5%, worst 30%).
- It also limits BM4 support loads to 21 and 15 of 30 within 5%.
- Bend and tee stress factors multiply moments, so they should come after
  the moments are right.

**Where things are today:**
- `src/core/linear-piping-analysis-consumer/inputxml-linear-unilateral-restraint-review.js`
  already flags supports whose solved reaction opposes the direction they can
  resist. It is called from `src/workspace/lfea-pipeline-analysis-controller.js`.
- Restraints are linearized as two-way FIXED in
  `inputxml-linear-structural-constraints.js`, which already carries
  `unilateralAction` per constraint. The disclosure code is
  `GENERIC_APPROX_UNILATERAL_LINEARIZED`.
- `src/core/fea-benchmarks/caesar-accdb-friction-solve.js` has a
  deterministic iteration pattern to copy: an iteration cap, a convergence
  record, and a determinism check.

**Plan:**
1. In the native execution path (`src/lfea/native-execution-authority.js`,
   `run()`), iterate:
   - solve;
   - release every one-way DOF whose reaction is in tension, i.e. against
     its allowed direction;
   - re-solve;
   - re-engage any released DOF whose gap closes;
   - stop when the active set stops changing, with a cap of about 20
     iterations.
2. Record the iterations and the final active set in the execution record.
   Label it, for example `LFEA_UNILATERAL_ACTIVE_SET_ITERATION`, on by
   default, and show it in the Results basis.
3. Make the derived supports in `derived-support-authority.js` report a
   lifted-off support as zero.
4. Re-measure:
   - BM4 support loads: `reports/lfea-bm4-cii-output-comparison.json` and
     its check;
   - `scripts/lfea-b31-sustained-caesar-comparison.mjs`.
   Then raise the thresholds.
5. Never block. If the iteration doesn't converge, publish the last state
   with a label.

Size: large.
